0001: # Tensix Performance Counters Guide
0002: 
0003: This guide documents the interface for controlling and reading Tensix hardware performance counters. It covers how to configure and read them from C++ and Python, which useful derived metrics you can compute, and how to test both the interface and the metrics. It consolidates the hardware documentation and aligns it with the implemented interfaces found in this repository.
0004: 
0005: ## Overview
0006: 
0007: Tensix cores contain five hardware performance counter banks (also referred to as "groups" in some hardware documentation). This guide consistently uses the term "bank".
0008: 
0009: | Bank | Description |
0010: |------|-------------|
0011: | INSTRN_THREAD | Instruction issue counts and stall reasons per thread |
0012: | FPU | FPU and SFPU operation valid signals |
0013: | TDMA_UNPACK | Unpacker busy signals and math pipeline status |
0014: | L1 | NoC ring transactions and L1 arbitration events |
0015: | TDMA_PACK | Packer busy signals and destination register access |
0016: 
0017: Each category has debug registers for control and two output registers:
0018: - `PERF_CNT_*0`: Reference period (optional, only used in mode 1)
0019: - `PERF_CNT_*1`: Mode + counter select
0020: - `PERF_CNT_*2`: Start/stop (rising-edge triggered)
0021: - `PERF_CNT_OUT_L_*`: Cycles counted in the measurement window
0022: - `PERF_CNT_OUT_H_*`: Event-specific count for the selected counter
0023: 
0024: Special registers:
0025: - `PERF_CNT_ALL`: Start/stop for FPU and INSTRN_THREAD groups simultaneously
0026: - `PERF_CNT_MUX_CTRL`: L1 counter multiplexer control register
0027: 
0028: ### L1 Mux Control Register
0029: 
0030: The L1 bank has 8 counter IDs (0–7), but the hardware provides 16 different signals to monitor. The `PERF_CNT_MUX_CTRL` register (bit 4) selects which set of 8 signals maps to those IDs:
0031: 
0032: | Bit 4 | Counter ID 0–7 Maps To |
0033: |-------|------------------------|
0034: | 0 | NOC Ring 0 transactions, L1 arbitration bundles, unpacker arbitration |
0035: | 1 | NOC Ring 1 transactions, TDMA bundle arbitration, extended unpacker/packer signals |
0036: 
0037: You must set this mux bit **before starting** the L1 counters to ensure you're measuring the intended signals. The L1 mux setting is latched at measurement start time. Changing `PERF_CNT_MUX_CTRL` while counters are running results in undefined measurements.
0038: 
0039: ### Mode Register Bits
0040: 
0041: The mode register (`PERF_CNT_*1`) controls counter selection:
0042: 
0043: | Bits | Field | Description |

0055: | 2 (Continuous, no ref) | Same as mode 0, but does NOT maintain the reference cycle count. |

0057: **Mode 0 vs Mode 2:** Both run continuously until stopped. Mode 0 tracks elapsed cycles in `OUT_L` (needed for rate calculations), while mode 2 omits reference cycle tracking. **Use mode 0 for most cases** since you typically need both event counts and cycle counts. 0058: 
0059: **Note:** The reference period register is ignored in modes 0 and 2.
0060: 
0061: ### Counter Slots
0062: 
0063: A "counter slot" is a single 32-bit configuration word in the per-thread L1 configuration buffer. Each slot (one config word) specifies which bank/counter/mux combination to read out after measurement. The interface supports up to 86 slots per thread, allowing you to capture multiple events in a single measurement window. Slots are processed in increasing index order; invalid slots (valid bit = 0) are skipped and produce no output entry.
