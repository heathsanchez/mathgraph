0033: # Overview
0034: 
0035: LLK testing infrastructure uses `Python`, more specifically it's testing framework called `pytest` to enumerate test variants from tests provided, compile necessary artefacts, and evaluate whether test kernels produce results in expected error bounds. Kernels themselves are written in `C++` using LLK API, and are compiled using our custom RISC-V compiler, called [`SFPI`](https://github.com/tenstorrent/sfpi), into `elf` files that are loaded to and executed on device using this test infrastructure's runtime.

0517: This will just pick the variants, so all other options like `--compile-producer`, `--coverage` and so on, can be used as usual and have the same semantic effects. You shall not pass `-n NUMBER` flag here to execute on multiple pytest worker, because you won't get valid order reproduction that way.
0518: 
0519: > You may indeed edit `./my_lovely_run.json` and change order of elements in the runner's list. You shall only edit order, not the contents of the list elements themselves.
0520: 
0521: ### Collecting coverage data
0522: 
0523: For collecting code coverage data, you just pass `--coverage` flag to both `pytest` commands. If you want to collect coverage, you **must** compile your variants with coverage flag enabled to be able to collect that information. Coverage **can't** be collected on performance tests, because collected performance data wouldn't adequatelly represent real-world kernel performance.
0524: 
0525: # Where do my compilation artifacts end up?
0526: 
0527: Default build directory is at `/tmp/tt-llk-build/`. Your test's artifacts will be at the same path as the one provided in the `test_name` argument in the `TestConfig`/`ProfilerConfig` object. All variants will be placed in folders corresponding to the hash of their compile time arguments. Header file `build.h` generated using passed configuration parameters is placed in its variant's folder.
0528: If coverage is enabled, all coverage data is merged at the end of execution of tests and placed in the `/tmp/tt-llk-build/merged_coverage.info` file. For more details consult [this section](infra_architecture.md#file-and-artefact-paths)
0529: 
0530: # How do I see what code did my tests cover?
0531: 
0532: After finishing compilation and execution of your tests with coverage enabled, run `./generate_coverage_report.sh` placed in the `./tt-llk/tests` folder. The generated report is placed in the same folder as your `./tt-llk` repo. For convenient preview of the coverage data, I'd recommend installing the [Live Server VSCode extension](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer). When it opens your browser tab, you'll see the `./coverage_report` folder. By clicking on it, you'll see `html` report of lines, files and folders your run covered.
