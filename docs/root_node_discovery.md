# Root Node Discovery

## Definition

A MathGraph root node is a **persistent load-bearing continuation point**.

It is not merely:

- high support;
- a high-yield table;
- a frequent motif;
- a cluster center.

A root is useful when its verified consequences continue to produce new
certificates, residual compression, constructor pressure, or named obstructions
after saturation and shadow-duplication penalties.

Residuals are membranes: boundary surfaces where the current language,
constructors, motifs, and certificates stop being sufficient. Discovery means
locating viability ridges and phase gates where a change of representation
turns stubborn residuals into verified certificates, named obstructions, or
constructor pressure.

## Discovery Pipeline

1. Generate candidate laws, motifs, certificate families, and obstruction basins.
2. Run through multiple filtrations.
3. Measure support, purity, holdout stability, null lift, and coverage.
4. Cluster shadow laws.
5. Compute effective filtration count after overlap/shadow discounting.
6. Score persistence, null lift, load-bearing coverage, residual compression,
   certificate pressure, constructor pressure, phase-gate strength, and
   viability-ridge strength.
7. Promote only non-shadow, persistent, null-resistant, load-bearing candidates.
8. Send promoted roots to constructor planning and certificate factories.
9. Treat failed elevations and saturated basins as obstruction pressure.
10. Distill certificates into Certificate Universe, Table Motif Atlas, Root Node
    Atlas, and Obstruction Atlas.

## Shadow Duplication

Duplicate motifs may be repeated views of the same root. High support can be
false strength when it comes from aliases, table shadows, or repeated views of
one support pillar.

Shadow roots should be clustered, discounted, or held. They should not be
deleted: preserving aliases keeps the discovery history auditable.

## Root Types

- obstruction root
- constructor root
- representation root
- certificate root
- residual root
- lawbook root

## Advisory Boundary

Root scoring is advisory. Root nodes do not verify or refute claims. Only
terminal certificates cross the truth boundary.

## Constructor Validation

Observed roots become generative roots only after constructor validation. A
root candidate is valuable when it can drive a narrow basin into constructor
families that produce verified certificates, residual compression, constructor
pressure, or named obstructions with lift over a null/random comparison basin.

The validation loop is:

```text
root candidate
→ basin
→ constructor family
→ verified certificates
→ null lift
→ promotion recommendation
```

Constructor validation still does not verify a root as truth. It measures
whether the root bears weight as scheduling and constructor pressure. Any FALSE
certificate produced during validation must pass through the existing
M0/importer path; finite search failure remains residual evidence, not proof.
